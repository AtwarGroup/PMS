SQL role tests exercise database authorization and concurrency, not password authentication. Actual password sign-in and the UI actions above were separately verified through secure browser authentication.

## Corrections and automated validation

- The restore drill now delivers verification SQL via Docker stdin, raises errors for failed validation, and aborts on `pg_restore` errors. Executable guard tests cover locked drills, production-target rejection, restore failure, and SQL failure. This does not establish successful restoration of a real backup.
- Task subscriptions now refresh when the browser reports returning online. Realtime resubscription re-reads changes missed during disconnection. Visible-page polling falls back to 15 seconds when the channel is unhealthy, retaining the two-minute interval when healthy.
- The actual compatibility module is exercised with controlled transport failures: failed reads/writes, failed child reads, reconnection, preservation of unrelated concurrent edits, 28 concurrent read consumers, subscription recovery, polling cadence, and listener disposal.
- All 80 JavaScript regression groups passed locally. Quality Gate and Pages deployment passed for the published recovery changes. Tasks UI and bridge cache versions are 2.5.53.

## Remaining limits

- In the cloud browser, externally created/changed task data did not immediately appear before a page refresh. Recovery changes passed controlled tests, but their post-publication live behavior and prolonged use still need verification. The root cause of the live Realtime delay is not established.
- Offline transport tests use controlled failures; the cloud browser API does not expose a supported live-network-offline switch. Do not label them as a real device disconnection test.
- The actual backup restore drill has not run. The GitHub connector does not expose workflow dispatch, and browser observation of the workflow page remained blocked by credential protection after the permitted recovery navigation. Manual workflow execution and its resulting logs remain required.
- Prior screen/theme coverage includes static and fixture-backed desktop/mobile checks; it does not establish a complete live review of every role and screen.
