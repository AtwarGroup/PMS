# Job effective dates and periodic review

Implemented as additive migrations, preserving existing job descriptions, published snapshots, assignments and approval history. No existing description was published, scheduled, reassigned or configured by this change.

Publication: publishers choose a Saudi-local effective date. Today releases immediately; future approval is stored separately while the job remains in the finalized approval state. UI shows approved/waiting for effective date and separates the library counter from awaiting approval. Existing snapshot remains authoritative. Pending/blocked schedules freeze the whole job row until reasoned cancellation. Cancellation and release share the job row lock. Repeated identical approval is idempotent. Internal Cron checks every five minutes; browser users cannot call the worker. Disabled approver or lost publication permission blocks release, with an actionable message. Existing publication triggers create the employee acknowledgement, app notifications and email outbox only when release occurs. Email delivery uses the existing outbox dispatcher; this change does not assert autonomous email delivery timing.

New assignment while a revision is pending uses the existing published snapshot for acknowledgement and publication email queuing, instead of the future revision. First publication remains unavailable until release.

Periodic review: opt-in configuration, active eligible owner, due date and 3/6/12 months. New annual configuration defaults to a year ahead. No-change review stores an immutable review event and next due date, preserving job revision, snapshot and acknowledgements. A changes-required finding opens a DRAFT_REVISION task with the actual requested changes, and preserves the published version. New publication clears that request and sets the next review date. Hourly internal worker materializes one periodic workflow task per configured cycle; task links use the established job review route. Archiving disables periodic reviews and retires outstanding periodic update requests without fabricating a completed review. Configuration and event tables have explicit select-only grants and RLS for job workflow owners/reviewer, not ordinary assigned employees. Assigned reviewers can record outcomes; DRAFT owners configure reviews. Optimistic revisions protect simultaneous decisions.

Validation: 86 JavaScript regression groups; actual lifecycle renderer tests, Saudi midnight and month-end cases. Authenticated database transaction covers existing authoring lifecycle, periodic task dedup/no-change/retry, requested changes and task, future snapshot/acknowledgement protection, early publication denied, inactive approval blocks, cancellation/reapproval, idempotent release and latest acknowledgement task. All synthetic changes roll back. Employee cannot invoke internal schedulers or configure reviews. Scheduled Cron actual run succeeded with an empty production queue; periodic worker tested in SQL and hourly schedule installed. Existing security advisor categories unchanged; no new exposed SECURITY DEFINER RPC or unprotected table.

UI uses the existing content cards, controls and theme. Shared pure renderer is used by production and lab/job-lifecycle-preview.html, an explicitly synthetic, no-database preview. Browser checking of this preview does not claim authenticated live browser approval or employee sign-in.
