# إصدار التوظيف — المسار المعتمد

نطاق النقل التوظيف فقط. ملفات upgrade.sql وtest-cycle.sql وtest-email.sql تحفظ اختبار التوافق مع الإصدار السابق؛ ليست بمفردها دورة العمل النهائية.

## الترتيب الصحيح للنقل

1. تحقق من مخطط اللايف وخذ نسخة من التعريفات والإعدادات، وشغّل preflight.sql للقراءة فقط. راجع أي طلبات أو عروض غير منتهية قبل تغيير مسارها؛ لا تتجاوز اعتمادًا سابقًا ولا تنقل سجلات التجربة.
2. للإصدار الأقدم فقط، طبّق upgrade.sql أولًا، ثم approved-workflow.sql لاستعادة دورة المالية وشؤون الموظفين. approved-workflow.sql يُطبّق في معاملة واحدة واختُبرت إعادة تطبيقه.
3. طبّق separate-approved-roles.sql. يفصل دور إعداد العرض عن شؤون الموظفين وينشئ أدوار المالية وشؤون الموظفين المستقلة. لا يضيف مستخدمين أو يفعّل وحدات تلقائيًا.
4. من إدارة المستخدمين، أسند الأدوار المعتمدة وفعّل التوظيف للحسابات المستهدفة فقط. المسؤولون المعتمدون: حمزة يوسف للمالية، أمجد الشيخ لشؤون الموظفين، أحمد منشي للتوظيف، أحمد اليافعي للرئيس التنفيذي، محمد باسنبل لتطوير الأعمال. تحفظ صلاحيات الوحدات الأخرى.
5. احفظ المسؤولين الخمسة في إعدادات المسار. يجب إتاحة الوحدة لمدير الإدارة المستخرج من الهيكل؛ لا يستبدله النظام بمعتمد عام عند غياب صلاحياته. الطلب القائم يحتفظ بإسناده حتى إجراء إعادة إسناد مخول وموثق.
6. انشر الواجهة الجديدة، وتحقق من ترتيب المالية ثم شؤون الموظفين ثم الرئيس التنفيذي، ومن مراجعة العرض لدى شؤون الموظفين والإدارة الطالبة ثم الرئيس التنفيذي. لا ترسل عرضًا حقيقيًا ضمن اختبارات النقل.

## الدورة والاستثناءات

الاحتياج: الإدارة ← المالية ← شؤون الموظفين ← الرئيس التنفيذي ← مسؤول التوظيف. رفض المالية يحال للرئيس التنفيذي؛ قبول الاستثناء يعيد الطلب لشؤون الموظفين. رفض شؤون الموظفين يحال للتطوير؛ قبول الاستثناء يحيله للرئيس التنفيذي. رفض الاستثناء يوقف الطلب ولا يبدأ الاستقطاب.

العرض: مسؤول التوظيف ← شؤون الموظفين ← مدير الإدارة الطالبة ← الرئيس التنفيذي ← المرشح. رفض شؤون الموظفين أو وجود استثناء راتب/مزايا يحال للتطوير، ثم يستكمل إلى مدير الإدارة والرئيس التنفيذي عند الموافقة. رفض الإدارة أو الرئيس التنفيذي يعيد العرض للتعديل. يمنع تجاوز المراجع أو الاعتماد الذاتي أو إرسال عرض غير معتمد.

## البريد

اختُبر الوصول على التجربة إلى Jobs@tiradorstores.com فقط. تستخدم الدالة أسرار RECRUITMENT_RESEND_API_KEY وRECRUITMENT_EMAIL_FROM ومفتاح RECRUITMENT_EMAIL_ENABLED. لا تغيّر المفاتيح العامة أو DNS للوحدات الأخرى. المرشح والراتب والشروط تؤخذ من نسخة العرض المحفوظة، ولا تؤخذ من المتصفح.

## التحقق

npm run test:recruitment:release يختبر التوافق مع اللايف السابق ثم الدورة المعتمدة بخمسة مسؤولين، وإعادة تطبيق النقل، والرفض والاستثناء ومراجعي العرض والمهام والإشعارات، وفصل الأدوار ومنع الإرسال غير المعتمد، والبريد المعزول. اختبارات قاعدة التجربة تستخدم بيانات مصطنعة ومعاملات متراجعة. دليل المستخدم: recruitment/user-guide.html.
