دليل المستخدم

شرح عملي لاستخدام نظام إدارة المهام حسب صلاحية الموظف والمدير ومدير النظام.

V1.3.2

1. مقدمة

ATWAR ONE – Tasks نظام مبسط لإدارة المهام اليومية والمتابعة والاعتماد، مع دعم التسلسل الإداري والإشعارات وسجل النشاط دون تعقيد أنظمة المشاريع الكبيرة.

الأدوار

الموظفيرى مهامه الشخصية ويبدأها ويحدث الإنجاز ويرسلها للاعتماد.
المديريرى مهامه ومهام فريقه ويتابع الأداء ويعتمد أو يعيد فتح المهام.
مدير النظاميرى جميع المهام ويدير المستخدمين والصلاحيات والهيكل الإداري.

2. تسجيل الدخول والواجهة الرئيسية

يتم الدخول بالبريد الإلكتروني وكلمة المرور المسجلين في Firebase Authentication. تتغير الواجهة تلقائياً حسب صلاحية المستخدم.

  • البطاقات العلوية تعرض إجمالي المهام والمكتملة وقيد التنفيذ وقيد الانتظار والمتأخرة.
  • يمكن البحث بالعنوان أو الوصف أو الملاحظات.
  • يمكن التصفية حسب الحالة والمسؤول.
  • يمكن ترتيب المهام حسب الافتراضي، الأحدث، الأقدم، الأولوية أو تاريخ الاستحقاق.

3. إنشاء مهمة وإسنادها

  1. اضغط إضافة مهمة.
  2. أدخل عنوان المهمة والوصف وتاريخ البداية وتاريخ الاستحقاق.
  3. حدد الأولوية.
  4. حدد المسؤول إذا كانت صلاحيتك تسمح بذلك.
  5. يتم الحفظ تلقائياً والمزامنة مع Firebase.
عند إسناد المهمة لموظف يصل إليه إشعار داخل النظام.

4. دورة عمل الموظف

قيد الانتظار←قيد التنفيذ←بانتظار الاعتماد←مكتملة
  1. اضغط بدء المهمة عند بدء العمل الفعلي.
  2. حدث نسبة الإنجاز والملاحظات أثناء التنفيذ.
  3. عند الانتهاء اضغط إنهاء المهمة.
  4. تنتقل المهمة إلى بانتظار الاعتماد ولا يمكن للموظف تعديلها.
عند انتقال المهمة إلى «بانتظار الاعتماد» يتوقف عداد التأخير عند لحظة إرسالها للمدير.
لا يستطيع أي مستخدم اعتماد مهمة مسندة إليه بنفسه حتى لو كانت صلاحية حسابه «مدير».

5. المهام الفرعية (Checklist)

يمكن تقسيم المهمة الرئيسية إلى خطوات صغيرة. عند وجود مهام فرعية يتم احتساب نسبة الإنجاز تلقائياً.

  • مثال: إنجاز 3 من 4 مهام فرعية = 75%.
  • تتعطل نسبة الإنجاز اليدوية عند وجود Checklist.
  • لا يمكن إرسال المهمة للاعتماد قبل إكمال جميع البنود.
  • الحفظ أو تحديد Checkbox لا يغير موضع الصفحة.

6. مراجعة المدير والاعتماد

عند إنهاء الموظف المهمة تصل للمدير بحالة «بانتظار الاعتماد».

  • اعتماد الإكمال: تتحول المهمة إلى مكتملة وتصبح للقراءة فقط.
  • إعادة فتح: يكتب المدير السبب وتعود المهمة إلى قيد التنفيذ مع إشعار للموظف.
  • الاعتماد متاح للمدير المباشر أو مدير النظام المخول.

7. الإشعارات

يظهر جرس الإشعارات في الشريط العلوي مع عدد الإشعارات غير المقروءة.

  • إسناد مهمة جديدة.
  • تعديل المهمة أو إضافة ملاحظة مدير.
  • بدء الموظف أو إنهاء المهمة.
  • المهمة المتأخرة.
  • اعتماد المهمة أو إعادة فتحها.
الضغط على الإشعار ينقلك مباشرة إلى المهمة المرتبطة ويفتح تفاصيلها.

8. لوحة المدير ونظرة الفريق

  • إجمالي مهام الفريق.
  • المهام المتأخرة.
  • المهام قيد التنفيذ.
  • نسبة الإكمال.
  • بطاقة لكل موظف؛ الضغط عليها يفلتر قائمة المهام لذلك الموظف.

9. سجل النشاط

يسجل النظام آخر 100 حركة لكل مهمة، ومنها:

  • إنشاء المهمة وتغيير المسؤول.
  • بدء العمل وتحديث الإنجاز.
  • الملاحظات وملاحظات المدير.
  • تحديث المهام الفرعية.
  • الإرسال للاعتماد والاعتماد وإعادة الفتح والإكمال.

10. إدارة المستخدمين - مدير النظام

  1. أنشئ الحساب أولاً في Firebase Authentication.
  2. من النظام افتح المستخدمون ثم إضافة مستخدم.
  3. أدخل الاسم والبريد والصلاحية والحالة والمدير المباشر.
  4. عند الإضافة الأولى فقط افتح إعدادات متقدمة والصق Firebase UID.
  5. بعدها يمكن تعديل المستخدم دون التعامل مع UID مرة أخرى.

12. أفضل ممارسات الاستخدام

  • استخدم عنواناً واضحاً ومختصراً.
  • حدد تاريخ استحقاق واقعي وأولوية مناسبة.
  • استخدم Checklist للمهام متعددة الخطوات.
  • سجل الملاحظات المهمة داخل المهمة بدلاً من الرسائل الخارجية.
  • راجع الإشعارات والمهام المتأخرة يومياً.
  • لا تستخدم حساباً مشتركاً لأكثر من موظف.

13. مشاكل شائعة

لا أرى مهمة معينة

تحقق من فلتر المسؤول والحالة والبحث.

لا تصل الإشعارات

تحقق من قواعد Realtime Database ومن ربط المدير المباشر.

لا أستطيع اعتماد المهمة

تأكد أن المهمة ليست مسندة لك شخصياً وأنك المدير المباشر للمسؤول.

لا أستطيع تعديل المهمة

قد تكون بانتظار الاعتماد أو مكتملة، وبالتالي تكون للقراءة فقط.

لا يظهر مستخدم

تأكد من وجود سجل المستخدم في Realtime Database وربطه بـ Firebase UID الصحيح.
