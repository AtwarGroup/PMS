## ترتيب التنفيذ

1. سلامة النسخة الاحتياطية وإثبات الاستعادة، وتصنيف ملاحظات الأمان؛ يُقدمان على التحسينات الشكلية.
2. خط أساس للأداء لكل عملية أساسية، وحصر القراءات البطيئة أو المكررة، ثم تحسين واحد قابل للقياس في كل حزمة.
3. تبسيط التنسيقات والمكونات والتوافق تدريجيًا مع اختبارات عدم التراجع.
4. قبول الاستخدام الواقعي للأدوار الأساسية، ثم إعادة تقييم موثقة مقابل الجدول.

## نتائج فحص البداية وحدوده

- فُحصت حالة الإنتاج الحالية وملاحظات الأمان والأداء من قاعدة البيانات، دون تعديل البيانات أو الصلاحيات.
- جميع الجداول المرصودة في المخططات public وprivate وmigration مفعّل عليها RLS. لم توجد منح قراءة/كتابة مباشرة لدوري anon وauthenticated على الجداول الداخلية في private وmigration، ولا منح جداول لـanon في المخططات الثلاثة. هذا دليل نطاق محدود، ولا يثبت وحده سلامة كل دالة أو عرض أو سياسة.
- ملاحظات SECURITY DEFINER تحتاج مراجعة التفويض داخل الدالة؛ وجودها وحده لا يثبت ثغرة. الجداول الداخلية المغلقة عمدًا لا تُفتح لإزالة تنبيه عدم وجود سياسة.
- وجود فهرس غير مستخدم في نافذة إحصائية لا يبرر حذفه، ووجود علاقة بلا فهرس لا يثبت بطءًا. يُربط القرار بخطة الاستعلام وعبء العمل.
- مراجع تفسير ملاحظات المنصة: [RLS دون سياسة](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)، [دوال SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)، [حماية كلمات المرور المسرّبة](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)، [فهارس العلاقات](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys). تظل ملاحظات إعداد المصادقة مفتوحة للمراجعة دون تغيير كلمات مرور المستخدمين.
- سجل التشغيل المجدول أظهر ست نسخ أسبوعية ناجحة متتالية، آخرها التشغيل 39883068276. لم يظهر تشغيل باسم استعادة ضمن كامل سجل التشغيل اليدوي المعاد من API (أربعة تشغيلات للنسخ). لا يثبت ذلك غياب كل نسخة منصة أو كل إجراء استعادة خارج GitHub.
- المتاح عبر الاتصال الحالي مشروعان: الإنتاج والتجريبي. لا يُعامل التجريبي كقاعدة قابلة للمحو؛ يحتوي أعمالًا متزامنة. تجربة الاستعادة تحتاج هدفًا معزولًا محددًا وصلاحية تشغيل آلية الاستعادة. لا تُنشأ موارد مدفوعة ولا تُستبدل بيانات التجريبي لمجرد رفع التقييم.

## الحزمة المنفذة أولًا: سلامة مرفقات النسخة

تسجل النسخ الجديدة حجم البايتات الفعلي وبصمة SHA-256 لكل مرفق، وتتحقق من الملفات والأعداد والمسارات وعدم التكرار. يُرفض التلف أو النقص قبل اعتماد النسخة وقبل الكتابة إلى هدف الاستعادة. تبقى النسخ القديمة قابلة للفحص والاستعادة، لكن تُعد الملفات غير المزودة ببصمات ملفات قديمة دون ادعاء التحقق من محتواها ببصمة أصلية.

الاختبارات تعمدت إتلاف ملف مع الحفاظ على طوله، وتقصيره وحذفه، وتغيير عدادات البيان وتكرار المسارات واستخدام مسار أو رابط رمزي خارج المجلد. تحققت كذلك من رفض الملف التالف قبل أي طلب إلى واجهة الاستعادة. هذه اختبارات محلية ببيانات مصطنعة؛ لا تحتوي نسخة بيانات إنتاج ولا تمثل تمرين تعافٍ فعليًا.
