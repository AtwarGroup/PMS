ATWAR ONE Modular Prototype V0.2 - Auth Flow
============================================

ENTRY POINT
-----------
landing.html
    صفحة البداية العامة.

login.html
    تسجيل الدخول التجريبي + محاكاة صلاحيات.

index.html
    الصفحة الرئيسية بعد تسجيل الدخول.

ATWAR ONE Modular Prototype V0.1
=================================

الهدف
-----
واجهة موحدة للمستخدم، مع Modules مستقلة تقنياً لتسهيل التطوير المستقبلي.

الهيكل
------
/index.html
    الصفحة الرئيسية

/tasks/index.html
    نظام المهام الحالي V1.3.16 كصفحة مستقلة.

/team/index.html
    صفحة الفريق.

/team/employee.html
    صفحة الموظف داخل Module الفريق.

/profile/index.html
    الملف الوظيفي.

/profile/job-description.html
    الوصف الوظيفي كصفحة مستقلة.

/profile/kpi.html
    مؤشرات الأداء كصفحة مستقلة.

/assets/css/shared.css
/assets/js/shared.js
    الهوية والتنقل المشترك فقط.

مهم جداً
--------
- هذه الحزمة Prototype وليست النظام Live.
- لا يوجد تعديل على Firebase أو Realtime Database أو Rules.
- لا يتم حذف أو نقل أي بيانات.
- كل Module يمكن تطويره لاحقاً بشكل مستقل.


V0.3 ROLE PERMISSIONS
---------------------
تسجيل الدخول لم يعد يطلب اختيار الدور.
اسم المستخدم وكلمة المرور يحددان الدور والصلاحيات.

حسابات الاختبار:
employee@atwar.local / 123456
manager@atwar.local  / 123456
admin@atwar.local    / 123456

الموظف:
- الرئيسية
- المهام
- ملفي الوظيفي
- لا يرى الفريق ولا الاعتمادات ولا الإعدادات.

المدير:
- الرئيسية
- المهام
- الفريق
- ملفي الوظيفي
- الاعتمادات.

مدير النظام:
- جميع ما سبق
- الإعدادات وإدارة النظام.

هذه محاكاة localStorage فقط وليست حماية أمنية حقيقية.
الحماية النهائية ستكون Firebase Authentication + Database Rules.


V0.4 UNIFIED PORTAL
-------------------
صفحة البداية أصبحت بوابة موحدة لثلاثة أنظمة:
1) نظام أطوار الداخلي -> Login + الصلاحيات.
2) ZenHR -> رابط خارجي يفتح في تبويب جديد.
3) Odoo ERP -> رابط المؤسسة الخارجي يفتح في تبويب جديد.

لم يتم دمج كلمات مرور ZenHR أو Odoo داخل ATWAR ONE.


V0.5 PORTAL REFINEMENT
----------------------
تحسين بصري لصفحة البوابة الموحدة:
- تمييز النظام الداخلي عن الأنظمة الخارجية.
- توضيح أن ZenHR وOdoo يفتحان بشكل مستقل.
- الحفاظ على نفس Modular Architecture والصلاحيات الحالية.


V0.6 CLEAN UNIFIED PORTAL
-------------------------
تم إلغاء أي تمييز بين الأنظمة.
نظام أطوار وZenHR وOdoo تظهر جميعها كأنظمة الشركة ضمن بوابة ATWAR ONE الموحدة.


V0.7 SCALABLE CORE
------------------
تم تحويل الإعدادات المتكررة إلى ملفات مركزية:

assets/js/systems-config.js
    تعريف أنظمة الشركة وروابطها.

assets/js/roles-config.js
    الحسابات والأدوار والصلاحيات التجريبية.

assets/js/routes-config.js
    المسارات الرئيسية للنظام.

modules.json
    تعريف Modules الحالية وحالتها والحد الأدنى للدور.

الهدف:
- إضافة نظام جديد إلى البوابة من ملف واحد.
- إضافة Role أو Permission من ملف واحد.
- تقليل تعديل الصفحات يدوياً.
- إبقاء كل Module مستقلاً وقابلاً للتطوير.
- الحفاظ على تجربة موحدة للمستخدم.

تمت إضافة "بوابة الأنظمة" داخل القائمة الجانبية في الأسفل فقط،
وليس في الهيدر الرئيسي، حتى تبقى واجهة العمل بسيطة.


V0.8 TEAM EXPERIENCE
--------------------
تم رفع مستوى تجربة الفريق وملف الموظف:

team/index.html
- بوابة متابعة الفريق.
- بطاقات الموظفين تبقى مختصرة للإدارة السريعة.

team/employee.html
- صفحة موظف احترافية مستقلة.
- نظرة عامة.
- المهام.
- الوصف الوظيفي.
- مؤشرات الأداء KPI.
- كل ذلك ضمن Module الفريق وليس مدمجاً داخل الرئيسية.

مبدأ معتمد:
الفريق = بوابة الوصول للأشخاص.
ملف الموظف = مركز معلومات الموظف المسموح للمدير برؤيتها.
Tasks / Job Description / KPI تبقى Modules/صفحات مستقلة وقابلة للتوسع.

لم يتم ربط Firebase حتى الآن.


V0.9 WORKFLOW REFINEMENT
------------------------
- تثبيت التصميمات المعتمدة وعدم إجراء تغييرات شكلية عليها.
- إزالة أي شعار صوري من صفحات الإدارة المالية عند وجوده؛ يبقى النص والهوية البصرية فقط.
- إضافة Module مستقل للاعتمادات للمدير وما فوق.
- بطاقة "بانتظار اعتمادي" في الرئيسية تقود إلى صفحة الاعتمادات.
- صفحة الاعتمادات تعرض ما يحتاج قرار المدير أولاً.
- لم يتم ربط Firebase ولم يتم تعديل النظام Live.


V0.10 MY WORKSPACE
------------------
تم إضافة Module مستقل باسم "مساحة عملي":
- ملاحظات شخصية سريعة Sticky Note.
- وصول سريع للمهام والملف الوظيفي.
- المدير يرى أيضاً الفريق والاعتمادات.
- ملخص بسيط لما يحتاج الانتباه اليوم.
- الملاحظات في Prototype تحفظ LocalStorage فقط لكل حساب تجريبي.
- لا تعتبر الملاحظات مهام رسمية ولا تدخل في Workflow الاعتماد.

لم يتم تغيير تصميم صفحة البداية المعتمد.
لم يتم تغيير التصميمات المعتمدة للإدارة المالية.
لم يتم لمس Firebase أو النظام Live.


V0.11 NOTIFICATIONS

لم يتم لمس النظام Live.


V0.12 GLOBAL SEARCH
-------------------
تم تفعيل مربع البحث الموجود أصلاً في الهيدر:
- Enter ينقل إلى مركز بحث مستقل.
- البحث يراعي صلاحية المستخدم.
- الموظف لا تظهر له نتائج الفريق أو الاعتمادات.
- المدير يرى الموظفين والفريق والاعتمادات.
- البحث الحالي Prototype على بيانات تجريبية ومسارات النظام.
- لاحقاً يمكن ربطه ببيانات Firebase الفعلية.

لم يتم تغيير التصميمات المعتمدة ولم يتم لمس النظام Live.


V0.13 MY PROFILE HUB

- بيانات الموظف الأساسية.

- ملخص أداء مختصر.
- ملخص المهام.

- الصفحة تتغير باسم ومسمى المستخدم المسجل.

الوصف الوظيفي وKPI بقيا صفحات مستقلة كما تم الاتفاق.
لم يتم تغيير صفحة البداية أو التصميمات المعتمدة.
لم يتم لمس Firebase أو النظام Live.


V0.14 ORGANIZATION
------------------
تم إضافة Module مستقل للهيكل التنظيمي.
الهدف ليس كشف جميع بيانات الموظفين، بل توضيح موقع المستخدم وعلاقاته التنظيمية حسب الصلاحيات.

التوجه النهائي:
- الموظف: موقعه في الهيكل + مديره المباشر.
- المدير: إدارته + فريقه المباشر.
- الإدارة العليا: نطاق أوسع حسب الصلاحية.
- الهيكل مرتبط لاحقاً بملفات الموظفين والوصف الوظيفي وKPI.

التصميمات المعتمدة لم تتغير.
Firebase والنظام Live لم يتم لمسهما.


V0.15 FOLLOW-UP
---------------
تم إضافة Module "المتابعات" وفق مبدأ Follow-up كعنصر عمل خفيف:
- انتظار رد.
- تذكير بمتابعة.
- تاريخ متابعة.
- ملاحظة قصيرة.
- إغلاق المتابعة عند الانتهاء.
- لا يحتاج Workflow كامل مثل المهمة.
- لا يؤثر على KPI أو نسبة إنجاز المهام.

في Prototype تحفظ المتابعات محلياً لكل مستخدم.
لاحقاً يمكن ربطها بقاعدة البيانات والإشعارات.
التصميمات المعتمدة لم تتغير وFirebase لم يتم لمسه.

V0.20 CONSOLIDATION
-------------------
هذه نسخة تنظيف وتثبيت، بدون إضافة Features جديدة.

1) صفحة البداية ATWAR ONE بقيت كما هي.
2) بعد تسجيل الدخول جميع الأدوار تدخل "الرئيسية".
3) الرئيسية تتغير محتوياتها حسب الدور.
4) القائمة الرئيسية اليومية:
   - الرئيسية
   - المهام
   - الفريق (للمدير وما فوق)
   - ملفي الوظيفي
5) الملاحظات والمتابعات والاعتمادات والهيكل والإشعارات والبحث و"يومي"
   تبقى وظائف مساندة وليست عناصر تنقل رئيسية.
6) تم استبدال صفحة المهام في Prototype بنسخة معاينة آمنة لا تحتوي SDK أو إعدادات اتصال بقاعدة البيانات.
7) تم إنشاء tasks/user-guide.html لمنع 404 داخل الحزمة.
8) تم استرجاع التصميم الاحترافي للملف الوظيفي من صفحة المدير المالي وحذف جميع الصور/الشعارات الصورية منها.
9) مصفوفة الصلاحيات تظل نموذج إعداد فقط حتى الربط الحقيقي.
10) لم يتم تعديل النظام Live أو قواعده أو بياناته.

المرحلة التالية بعد اعتماد V0.20:
تثبيت V1 Architecture، ثم إعداد بيئة اختبار منفصلة للربط الحقيقي.
